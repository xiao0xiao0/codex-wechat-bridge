# v0.9.34：固定回复码、改名兼容与通知刷新

本版在 v0.9.32 基础上合并此前仅本机使用的 0.9.33 通知刷新改进，并新增不依赖微信引用信息的固定回复码续接。

## 日常怎么用

完成通知会包含任务名称、回复码和结果。例如：

```text
【已完成】示例任务
回复码：ABC234
本轮结果……
```

继续这个任务时发送：

```text
/回复 ABC234 请继续完善第二部分
```

ABC234 仅为示例，请使用自己的通知中的实际六位回复码。无需引用；普通聊天文字不会执行。发送 `/回复码` 可查询最近最多 30 个可核实任务及当前名称，适用于没有回复码的旧通知。

## 固定身份和改名

- 回复码绑定不可变任务 ID，不绑定任务标题或通知时间。同名任务和分支分别拥有自己的码。
- 改名、等待数小时、服务重启及 `/清空` 不改变已有绑定；进入队列和真正提交前都会重新读取当前任务名。
- 引用返回原消息编号或包含回复码的正文时，仍支持引用续接。未知或冲突标识不执行；不再接受按时间、数字消息编号时钟、标题、最近任务推断的目标，也不再信任旧版本通过时间推断记住的引用别名。
- 回复码不是登录凭据。仍只接受扫码绑定账号，并要求先启用双向执行。

## 通知刷新与防重放

- `/诊断` 报告健康状况；`/刷新` 会核对近期任务的最新完成事件，补入符合条件的遗漏通知，并投递待发文字。
- 刷新先回执，再报告连接、补入、成功投递和剩余数量。扫描及单次发送有上限，达到上限会明确说明。
- 保留发送检查点、分支历史过滤和清空水位；已发送、已抑制及无法核实的事件不强制重发，不重置监控偏移。
- 长结果每段都包含回复码。附件独立排队，默认关闭自动上传；`.md`、`.js`、`.py` 等文件继续排除。

## 升级和已知限制

按 [仓库安装教程](https://github.com/xiao0xiao0/codex-wechat-bridge/blob/main/docs/%E5%AE%89%E8%A3%85%E6%95%99%E7%A8%8B.md) 更新后，在微信发送 `/诊断`，应显示 0.9.34。无需清空状态或重新绑定微信。

回复码解决的是“准确选择任务”，并未替换桌面提交方式：Windows 需保持解锁，Codex 窗口需可操作。输入框或任务身份无法核实时不提交，不启动第二个 App Server 抢占现有任务，也不自动重试失败命令。不能承诺锁屏无人值守续接。

部分微信客户端不返回原引用标识或正文，单纯引用可能被拒绝，此时用固定回复码续接。`/分支` 仍需可核实引用；`/附件` 还须核实原消息编号，因为固定任务码无法指定旧的完成轮次。此类客户端可先在 Codex 完成分支或取附件。`/回复 CODE /分支 ...` 只把正文交给原任务，不是桥接分支指令。

迁移或备份时请私下保留整个本地状态目录，尤其 `reply-codes.json` 和初始化标记；记录缺失或损坏时不会静默重分配旧码。缺码不会阻断普通完成通知，但不能据此执行任务。不要把状态目录、凭据、消息或私人日志上传 GitHub。

## 验证范围
